# Conversation report links used the author's loopback address

John, Transformer Math, source turn 4d7dc1d0-3a90-4f5e-9c08-a2ad0b2b5622, 9 September 2026: “All these links die when I try and open them, except for the paper pdf.”

The delivered report URLs hard-coded http://127.0.0.1:8777. The chat renderer copied them verbatim and recognized only absolute HTTP links. The workflow renderer instead built same-origin, authenticated links. The campaign's previous test injected request authorization everywhere and checked only the chat label; it did not click the actual chat URL. Thus its workflow success did not prove conversation delivery. The client's failing origin was not recorded; the loopback defect is established from the actual URL and normal remote addressing semantics, not invented browser telemetry.

Implemented: the chat renderer accepts contained artifact paths and normalizes the historical loopback artifact origin to the current page's origin. Only recognized internal destinations receive the current page's authentication. External paper URLs stay intact; userinfo and lookalike hosts do not receive credentials. The campaign replaced report cross-link annotations with origin-relative URI actions and made its builders retain that behavior. Actual replacement conversation URLs use the verified HTTPS network address and also parse in the old renderer.

Acceptance: the live browser clicks actual historical report links and exact replacement URLs, verifies rendered PDFs and served hashes, follows current local references, and opens a reference from inside the actual PDF. Normal login creates the browser cookie; no request interception supplies hidden report authorization. The focused JavaScript gate checks relative/same-origin/legacy links, external URLs, lookalike hosts, userinfo, wrong loopback ports and token replacement. Receipts live in Transformer Math/Hierarchical AR Networks/reports/access-check, with a human-facing registered report in reports/REPORT-ACCESS.md.

Activation boundary: updated JavaScript is served to newly loaded cockpit pages. Existing tabs may retain old code until reload. No global service restart is needed for the replacement HTTPS URLs or repaired PDFs, and none was performed. The successful actual browser check is not a claim to have observed John's own device.

General correction promoted to the canonical user-global rules: verify the exact link being delivered on the intended surface and origin; a different privileged workflow fetch is not sufficient. Future renderer changes should keep this regression in their acceptance checks.

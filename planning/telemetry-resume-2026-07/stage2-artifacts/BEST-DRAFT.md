# Anchor — Honest Telemetry + Warm Resume — Implementation Plan (Foreman-ready)

test-command: python -m pytest tests/ -q

**North Star:** Every Anchor session — interactive ConPTY or one-shot job — leaves an honest, machine-verified trail of what it cost and what it accomplished, so the project rollup's numbers mean 'measured truth, not zero-by-omission,' and clicking ANY session tile reliably opens a warm terminal that narrates what was done, what was produced, and what comes next.

## Stage-1 process-integrity record — review-transport failure + Round-6 convening protocol (engine-facing; removed only by a CONVENED round)

- **Rounds 2–5 are VOID (infrastructure failure, not convergence).** Shark rounds 2–5 produced ZERO reviews: every Shark spawn failed with ENAMETOOLONG because the full plan text was passed on the spawn command line. A round in which no Shark actually read the artifact is not a review round. **The dry verdicts of rounds 2–5 are VOID, and the dry counter is RESET to its post-round-1 state.** No convergence or lock claim may cite r2–r5; the last CONVENED Shark Tank remains Round 1.
- **HALT-first rule.** The next engine step is NOT another review round on the broken transport — it is a HALT to the user with this infrastructure-failure report: (a) rounds 2–5 produced zero reviews due to spawn ENAMETOOLONG; (b) the r2–r5 dry verdicts are void and the dry counter is reset to post-r1; (c) the transport fix below. Review resumes only after the user approves the transport fix.
- **Transport fix (the normative delivery rule — the plan text NEVER rides the spawn command line again):** deliver the Shark prompt via a temp-file path or stdin (the job_runner/gate_adapter pattern), OR pass only the round artifactPath (stage2-artifacts/round-6) and have each Shark Read the artifact itself.
- **Round-6 convening protocol (normative):** (1) each Shark must return `answerable: yes` BEFORE its findings are counted; a round containing ANY transport-abstain is VOID and must not touch the dry counter; (2) Sharks review the CURRENT plan artifact FRESH (stage2-artifacts/round-6), explicitly re-testing whether each of the six carried r1 disputes is now RESOLVED-IN-TEXT or STILL-OPEN — starting with D1 (the warm-open contract, the de facto 2-agree BLOCKER) and D2 (the 100%-trail-record invariant); (3) the round harness must demonstrate that topic dedup merges same-substance findings ACROSS reviewers, so a real 2-agree BLOCKER can never again be split into two agreement:1 rows.

## Locked design decisions (Stage-1; carried VERBATIM into the W1 North Star amendment)

- **ONE capture mechanism + ONE ordered fallback + ONE PROMOTION RULE (Stage-2 lock precondition).** The capture mechanism is the engine's own session JSONL sidecar (`~/.claude/projects/<slug>/<session-uuid>.jsonl`), correlated by `engine_session_id` captured AT LAUNCH. The ordered fallback rule is: (a) primary correlation = slug-dir watch in a tight launch window under the session lock; (b) fallback correlation = PTY-banner parse; (c) both miss ⇒ the session records state='unmeasured(uncorrelated)'. **PROMOTION RULE (deterministic — no runtime judgment call):** the slug-dir watch is the correlation of record; the banner parse is consulted ONLY when the watch window closes with zero candidates, and its UUID is then PROMOTED to correlation-of-record and stamped `correlation_source='banner'`. If a late watch candidate subsequently appears and DISAGREES with a promoted banner UUID, the session is re-stated `capture-failed(correlation-conflict)` — never silently re-pointed, never averaged. There is NO second capture mechanism, NO estimation, NO third correlation path. The W1 spike validates (a)/(b) and the promotion windows against the REAL engine, and its findings are folded into THIS section BEFORE Stage 2 locks; if the spike falsifies the sidecar shape or the correlation windows, Stage 2 does not lock until this section is rewritten from the observed truth. W4 implements THIS rule and nothing else — the build agent never chooses between mechanisms at build time or runtime; Foreman receives exactly one mechanism, one fallback, one promotion rule — never a menu.
- **Trail record schema (NORMATIVE — the exact Tier-1 record shape).** Every session/job terminates in exactly ONE trail record with these fields: `session_id`; `engine_session_uuid` (nullable ONLY when state='unmeasured' with reason='uncorrelated' or 'pre-feature'); `state` ∈ {measured, partial, unmeasured, capture-failed}; `reason` (enum, REQUIRED on every non-measured state: parked · heartbeat-only · engine-switch-segment · sidecar-pruned · uncorrelated · gemini-segment · pre-feature · crash · job-crash · correlation-conflict · parse-error); `error_class` (REQUIRED iff state='capture-failed': the parser exception class or 'zero-usage-with-messages'); `tokens_in`/`tokens_out`/`duration_s` (present iff measured/partial); `cost_usd` (nullable — present ONLY when the engine itself reported nonzero costUSD; NEVER defaulted to 0.00); `correlation_source` ∈ {watch, banner, none}; `bucket` ∈ {work, orientation}; `finalized_at`; `finalized_by` ∈ {inline, boot-reconcile}. A shared validator enforces this schema on every write; free-text states/reasons are impossible. **UI render rule (part of the lock):** a capture-failed record renders a red-tinted badge `capture failed — <error_class>` and its COST CELL renders an em-dash '—' — structurally never '$0.00' and never any number; grey unmeasured renders '— (reason)'; measured renders numbers. Because only state='measured' records carry numeric token/cost fields at all, a non-measured state structurally CANNOT render as $0.00 — there is no numeric value to render. The three are asserted DOM-distinct in W5 so capture-failed can never be visually confused with $0 or with unmeasured.
- **Two-tier honesty model (the reframed 'EVERY' invariant).** The invariant in one sentence: **every session ends measured, partial(reason), unmeasured(reason), or capture-failed(error_class) — never $0-by-omission, never record-less** — and the ≥90% measured-rate is DEMOTED to Tier-2 ops health, structurally unable to gate correctness. TIER 1 — INVARIANT, test-pinned, RED on violation: 100% of sessions, across EVERY end state in the W4 end-state matrix, leave EXACTLY ONE trail record conforming to the normative schema above (enum state + enum reason, never free text). 'No record at all' and 'measured-$0-by-omission' are each impossible-by-construction and each has a dedicated test that fails if it ever occurs. TIER 2 — OPS METRIC, warn-level only, never a correctness gate: the measured-rate ('measured 14/17 sessions (30d)') is stamped on the rollup and tracked against a ≥90% one-week target; per the locked healthcheck severity rule it may only ever `report.warn`, never redden the banner.
- **Boot-reconcile exception + bounded-read rule (the ONLY deferred finalization — the INVARIANT is ABSOLUTE, the READ is BOUNDED).** Finalization is INLINE at the end-state handler for matrix rows 1–5 and 10. Rows 6–9 (Anchor crash · host power loss · cold NSSM restart · boot orphan-reap) are the SINGLE permitted exception: they are finalized by the boot usage reconciler, which runs as part of the existing boot reconcile BEFORE any record is re-statused terminal/idle and BEFORE the first dashboard rollup render — that ordering is the ABSOLUTE rule: the UI never shows a pre-reconcile zero, no exceptions, no 'eventually'. The READ that satisfies it is BOUNDED, never a scan: the reconciler visits ONLY the pending set (records whose durable W2 launch-time anchor exists and whose cost_final flag is unset), resolves each sidecar BY ITS STORED UUID path — never a directory walk of the home store — applies a fixed per-record parse budget, and on any miss or budget overrun writes the honest terminal state ('partial(heartbeat-only)' or 'unmeasured(…)') and moves on. Total boot work is O(pending records), independent of sidecar-store size; the reconciler can therefore never hang or degrade boot, and 'absolute invariant' and 'bounded boot-time read' are BOTH satisfied by construction rather than traded off. No other code path may defer finalization; a grep-level suite assertion pins that `finalized_by='boot-reconcile'` is writable ONLY by the rows-6–9 reconciler. **Concrete crash walkthrough (the adjudication scenario — hard power loss after session start, BEFORE any end-path snapshot):** where reconcile finds the truth, in order: (i) the W2 durable launch-time anchor — written atomically at start, BEFORE the PTY/engine spawns (the W2 ordering rule), so any session whose engine ever ran has an anchor on disk; an absent anchor means the engine process was never launched, so there was no spend to account; (ii) at next boot the anchor (cost_final unset) places the session in the pending set; (iii) the reconciler opens the sidecar AT ITS STORED-UUID PATH — the ENGINE'S OWN append-per-message file on the same disk, which survives Anchor's death by construction and survives power loss whenever the OS flushed it (the W1 spike observes the real flush behavior); (iv) sidecar missing/empty ⇒ the last 120s heartbeat snapshot in `.anchor/` ⇒ 'partial(heartbeat-only)'; (v) neither ⇒ 'unmeasured(crash: sidecar-pruned)'. Every branch terminates in a schema-valid record before the first rollup render; no branch renders $0, and no branch leaves the session record-less. This walkthrough is pinned as the row-6/7 named tests in W4.
- **Warm-open contract (the click-to-live-PTY decision, RESOLVED — normative UX click table).** Clicking ANY session tile opens the session window whose REAL xterm pane — the SAME buffer a live PTY attaches into — renders the Layer-1 narration AS TERMINAL OUTPUT within 200ms: what was done, what was produced, what comes next, with links. It is a terminal, never an HTML mock; rendering 'warm terminal' on any non-xterm surface is a BLOCKER. **The Layer-1-view-vs-auto-attach question is DECIDED, not open: auto-attach fires ONLY for a RUNNING tile; every non-running class is view-first with exactly one explicit live action.** The click table: **RUNNING tile → 1 click** = narration header lines then AUTO-ATTACH to the live stream in the same pane (1 click to live PTY, no second action). **NON-RUNNING tile (parked · evicted · done · failed · discovered · finished job) → 1 click** = the warm narrated terminal, plus ONE explicit `▶ Resume live` action that attaches/starts the PTY into that SAME pane, swapped in only after attach-ack + replay-complete (≤5s, else a styled error state with retry over the still-visible narration) — 1 click warm + 1 explicit action to live. There is never a third action, never a second window. Mutating/ACTION prompts remain v10 paste-NOT-submit in every case. **North Star reading (adjudication record — cite the text, not preference):** the North Star's own words are 'clicking ANY session tile reliably opens a warm terminal that narrates what was done, what was produced, and what comes next.' The predicate the click must satisfy is a WARM TERMINAL THAT NARRATES — the sentence's object is a terminal narrating those three things, not a live engine process. This contract satisfies that text literally for every tile class: one click always opens a REAL terminal (the xterm pane, <200ms) that narrates exactly those three things. Auto-attaching a live engine to every historical/done/discovered tile is NOT what the text asks and would violate three sibling locks (no unattended engine spend, no auto-submitted ACTION prompts, v10 paste-NOT-submit); so live attachment is automatic precisely where a live process already exists (RUNNING) and exactly one explicit action away everywhere else. Layer-1-narration-plus-`▶ Resume live` is therefore RULED an honest reading of the North Star, not a violation; a challenge to this ruling must cite which North Star words it fails, not a preference for a different UX. This contract is pinned verbatim in the W1 amendment and screenshot-asserted per tile class in W6.
- **Eviction labeling sub-contract (exact strings + explicit eviction contract, LOCKED).** An evicted-parked tile carries the badge text `evicted — worktree reclaimed · docs persisted` (never 'parked', never 'idle', never unlabeled grey); its warm terminal narration, when escalated, includes the exact line `resumed from persisted docs (worktree evicted)`; and the escalation ALWAYS opens a NEW session joining the SAME chain via parent_session_id — the UI never claims or implies 'reattach' for an evicted session. Both strings are screenshot- and DOM-asserted in W6; the record/chain/summary/finalized-cost all survive eviction (only the worktree is reclaimed), so an evicted session stays MEASURED. **Eviction contract (explicit — W6 implements exactly this):** budget knob = `ANCHOR_PARKED_WORKTREE_BUDGET` (int, default 8, env-overridable); eviction CANDIDATES = parked `STATUS_IDLE` sessions ONLY — never a RUNNING session, never a session with a live PTY, and never before eviction VERIFIES the session's docs are persisted to main and its summary cache exists (if a pre-hook park left either missing, eviction performs the persist/summary-schedule itself FIRST, then reclaims — eviction can never destroy the only copy of anything); ORDER = oldest last-activity first, deterministic; ACTION = reclaim the worktree only, stamp the record evicted, leave record/chain/summary/finalized-cost untouched; the dashboard shows the parked-worktree count against the budget.
- **Orientation-cost bucketing (LOCKED — with the explicit trigger contract).** The read-only plan-mode orientation job costs real tokens and is measured like any row-10 one-shot job — but its ledger rows carry `bucket='orientation'` (a first-class ledger/schema field), it rolls up in a SEPARATE visible 'orientation overhead' line on the project rollup ('+ N tok orientation overhead'), and it is NEVER folded into the session's own work cost, the lane totals, or the measured-rate denominator's work spend. Hiding orientation cost or folding it into work totals is a BLOCKER-level dishonesty; a W5 test pins the separation. **Orientation trigger contract (explicit — W6 implements exactly this):** the orientation job fires (a) on the explicit per-tile 'Orient' action, and (b) auto-fires AT MOST ONCE per warm-open of a NON-RUNNING tile whose cached summary is absent or stale (older than the session's last activity) — deduped per session per boot, never re-fired while one is already running or already ledgered for that session this boot; it always runs `permission_mode='plan'` (read-only) through job_runner's row-10 path; its ledger row carries `bucket='orientation'` plus a reference to the ORIENTED session_id for drill-down while remaining excluded from that session's work cost and from lane totals.

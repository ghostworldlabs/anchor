**North Star:** Every Anchor session — interactive ConPTY or one-shot job — leaves an honest, machine-verified trail of what it cost and what it accomplished, so the project rollup's numbers mean 'measured truth, not zero-by-omission,' and clicking ANY session tile reliably opens a warm terminal that narrates what was done, what was produced, and what comes next.

## Locked contracts (plan-level, relitigating any of these is a BLOCKER)

**Objection-survival rule (meta, LOCKED).** Each of the four previously-disputed resolutions below carries an explicit *Original objection & why this resolution survives it* clause. A Shark pressing a lock must press against that clause — showing the written resolution fails to defeat the recorded objection — not merely re-raise the objection the clause already answers. A lock whose survival clause is refuted is a legitimate BLOCKER; a lock re-argued without engaging its clause is relitigation.

**The click contract (LOCKED — dispute 1, pre-resolved: the passive warm view IS the narrating terminal, with in-view PTY escalation).** The North-Star phrase 'clicking ANY session tile reliably opens a warm terminal that narrates' is satisfied by a TWO-LAYER contract, and the plan formally defines each layer so 'warm' and 'reliably' are measurable, not adjectives:
- **The first-click sentence (LOCKED — test it VERBATIM against the North-Star clause 'clicking ANY session tile reliably opens a warm terminal that narrates'):** *The first click on any session tile — running, parked-idle, evicted-parked, done, failed, discovered/brownfield, or finished one-shot job — opens within 200ms a terminal-chrome window that narrates what was done, what was produced, and what comes next.* Every word is bound: 'any session tile' = the exhaustive Playwright tile-class matrix; 'opens' = exactly one click, no menu hunt; 'warm terminal' = Layer 1's terminal-styled window in the terminal window chrome, rendered from cached/durable local data; 'narrates' = the narration spine (done / produced / next); 'reliably' = the <200ms, structurally-never-blank budget. Playwright asserts this sentence per tile class, and the Judge evaluates the plan against THIS sentence, never a paraphrase.
- **Layer 1 — the warm narrated view (every click, every tile class).** First click opens the session window rendering the NARRATION SPINE — what was done / what was produced / what comes next — as a PURE DETERMINISTIC RENDER: no PTY spawn, no synchronous model call, no network. Reliability budget: renders in <200ms from cached/durable local data; it CANNOT be blank because its floor is a deterministic template over registry facts + doc roles (defined below) that is total over every registry/effort record. When no cached summary exists yet, Layer 1 additionally shows an honest 'summary generating…' badge while the EXISTING background enrichment runs (see the narration-floor lock) — a badge over content, never a spinner instead of content. This view IS the North-Star 'warm terminal' for a plain click, and the plan DEFENDS that identity rather than conceding it as a compromise: Layer 1 renders inside the SAME session-window terminal chrome Layer 2 lives in (same window, same monospace terminal surface styling, same title bar and controls), so escalation is an in-view pane transition, never a navigation or a second window — the user experiences one terminal window that starts narrating instantly and can go live in place.
- **Layer 2 — in-place live escalation ('▶ Resume live', same window).** An explicit control in that same window escalates to a live PTY IN PLACE (the window transitions; no second window). Reliability budget: the terminal pane swaps in ONLY after the WS attach-ack + replay-complete signal; if no ack within 5s the window shows an explicit, styled error state with a retry control and the narration still visible underneath — a blank pane is a protocol impossibility, not a rare bug. On escalation, the read-only orientation narration executes per the Phase-0 fork lock; ACTION prompts remain v10 paste-NOT-submit.
- **Click-path ruling (explicit, so the North-Star sentence is checkable against the plan text):** from any session tile the user performs exactly ONE action (the tile click) to reach a warm, narrating, terminal-styled window — Layer 1 — and exactly ONE further explicit action ('▶ Resume live', in the same window, never a new window) to reach a live PTY. The plan RULES that the North-Star sentence is satisfied at action 1: Layer 1 is 'a warm terminal that narrates' (terminal chrome + narration spine), and 'reliably' is its <200ms / structurally-never-blank budget. The live PTY is one explicit action away for every tile class — never more, and never a hunt through menus. The Playwright matrix asserts this 1-click/2-action path per tile class; a change that inserts a third action into the path to live is a BLOCKER.
- **Strict-literal-reading rejection (recorded, so this ruling is pressable rather than implicit):** the plan CONSIDERED the alternative reading in which 'opens a warm terminal' means a LIVE PTY at action 1, and REJECTS it with recorded rationale: (a) for done / failed / discovered / evicted-parked / finished one-shot-job tiles there is no live PTY to open — a spawn-per-click would mint new sessions and worktrees the user never asked for, mutating state from a read gesture; (b) a PTY spawn + engine launch is multi-second and engine-availability-dependent, so under the strict reading 'reliably' is unsatisfiable for most tile classes and the North-Star sentence becomes untestable as written; (c) Layer 1 IS a terminal in every sense the sentence binds — terminal chrome, terminal styling, the narration content — with the live PTY exactly one explicit in-window action away for every class. If the user rejects this ruling at the Stage-1 gate, the plan HALTs for re-framing rather than silently reinterpreting the sentence.
- ***Original objection & why this resolution survives it:*** *the objection was that a rendered view is not 'a terminal', so first-click-opens-a-render betrays the North-Star sentence.* The resolution survives because it does not weaken the sentence to fit the render — it BINDS every word of the sentence to a measurable property Layer 1 actually has (terminal chrome, narration spine, <200ms, never-blank), records and rejects the strict reading with three concrete reasons (state-mutation-from-a-read-gesture, unsatisfiable-'reliably', untestability), keeps live exactly one in-window action away for EVERY class, and — decisively — routes the residual disagreement to the user at the Stage-1 gate with an explicit HALT-for-reframing path instead of a silent reinterpretation. The objection can still be pressed, but only at the gate against the user's authority, not against an ambiguity: there is none left.
- **Eviction ruling (BINARY, LOCKED — dispute 4, pre-resolved: eviction is KEPT, WITH the evicted-tile click contract below).** The cut-eviction alternative was evaluated and REJECTED: without eviction, parked worktrees (each a full checkout) grow without bound and there is no reclamation story; because the v8 keystone already persists every session's docs to main before reap, eviction loses nothing recoverable. Keeping eviction OBLIGATES the plan to the evicted-tile resume sub-contract below — an evicted tile with undefined click behavior would violate 'clicking ANY session tile', so the sub-contract is part of this lock, not an optional nicety.
- **Evicted-tile resume sub-contract (named, part of this lock, and COMPLETE — eviction reclaims ONLY the worktree):** an EVICTED-parked tile (worktree reaped, docs persisted to main) Layer-1 renders from the main-persisted docs with an explicit 'evicted' badge, and its Layer-2 escalation is a NEW session seeded via the W3 continue/seed path whose orientation opens with an explicit 'resumed from persisted docs (worktree evicted)' line — the UI NEVER claims a reattach it cannot perform. Everything except the worktree SURVIVES eviction: the registry record (the tile persists), its chain_id/lineage, its cached summary, and its finalized cost record (an evicted session stays MEASURED in the rollup — eviction never zeroes or un-measures anything); the Layer-2 replacement session joins the SAME chain via parent_session_id, so lineage is continuous across eviction.
- ***Original objection & why this resolution survives it (eviction):*** *the objection was that eviction creates a tile class whose click behavior was undefined, silently breaking 'clicking ANY session tile'.* The resolution survives because the choice was made BINARY (keep-with-contract vs cut, no third 'keep and hope' state), the kept branch carries a COMPLETE sub-contract enumerating exactly what survives (record, chain, summary, cost) and what does not (only the worktree), the Layer-1 render and Layer-2 escalation for the evicted class are both specified and both land in the exhaustive Playwright matrix (Phase 5's eviction test asserts the evicted tile renders per its class definition the moment eviction creates it), and honesty is preserved end-to-end: the UI never claims a reattach, the rollup never un-measures. An evicted tile is now the BEST-specified class in the plan, not the undefined one.
- Weasel-word guard: the plan never claims Layer 1 'is live' — it claims Layer 1 narrates and Layer 2 is one explicit click away in the same window. Both layers, per tile class, are in the Playwright sign-off matrix.

**The historical-attribution position (LOCKED): defer-and-badge.** Pre-feature sessions are NEVER retroactively attributed from surviving ~/.claude sidecars — no backfill mechanism ships in this plan. Every pre-feature session is badged 'unmeasured (pre-feature)' via the reason enum, and Phase 6 reports COUNTS of unmeasured-pre-feature sessions (and the prospective capture rate on new sessions) — never an 'attributed/recovered %' metric, which would rest on pruned or misattributable sidecars. Rationale recorded in Phase 0: sidecar→session correlation is only trustworthy when the UUID is captured AT LAUNCH; mtime-window guessing over historical files violates the honesty contract. If a later effort wants sidecar archaeology, it is a NEW plan with its own correlation-confidence design.

- ***Original objection & why this resolution survives it:*** *the objection was that the Gemini gap was carried as prose ambiguity — waves could build against an assumed scope and the rollup's 'measured truth' claim would silently exclude real spend.* The resolution survives because the ambiguity is now structurally impossible to build against: the scope question is a named artifact with enumerated options and stated consequences, its status field says RULED (letter C), the build system treats 'cites an unruled option' as a HALT (not a warning), the UI consequence of every option is written down in advance (so no option can smuggle in a complete-looking number — even the cheapest option renders 'partial (gemini segment unmeasured)'), and the recommendation is explicitly severed from the ruling so the drafters' preference cannot masquerade as the user's decision.

**The narration floor (LOCKED — dispute 3, pre-resolved: lazy on-first-click enrichment with an honest 'summary generating…' interim state; deterministic template as FLOOR; batch backfill CUT; seed-only rejected as ceiling).** 'Narrates' is satisfied at the floor by a DETERMINISTIC template over durable facts — 'ran <skill/lane> in <lane> (<dates>, <status>); produced: <doc-roles list with /report·/artifact links>; next: <NEXT-PROMPT.md / pending_paste / stage-derived next step>' — which requires zero model calls and is total over every tile class. **Three candidate narration models were evaluated, and the evaluation is recorded here so the choice is a ruling, not a default:** (i) **Degraded-seed-only** — the deterministic template forever, no model enrichment: $0 and always instant, but on long or conversation-heavy sessions registry facts + doc roles under-describe 'what was done' (a 3-hour research session renders as one lane/date line), so as a permanent ceiling it FAILS the North-Star 'narrates what was done' bar — RETAINED AS THE FLOOR ONLY, rejected as the ceiling. (ii) **Eager batch backfill** — pre-generate model summaries for every summary-less session: at any tile the user actually clicks it delivers narration no earlier than the lazy path (Layer 1 is already total and instant at click time), it spends the per-summary cost on the never-viewed tail, and it drags in a throttling/scheduling design — CUT as a phase deliverable. (iii) **Lazy enrichment on first tile-open with an honest generating state** — the click renders the deterministic floor IMMEDIATELY; when no cached summary exists, the open triggers the EXISTING background generation path (the v3 accordion machinery + summarize-on-finish, unmodified) and Layer 1 shows an explicit 'summary generating…' badge over the template; on completion (and on every later click, from cache) the enriched text replaces the template's 'what was done' line — **CHOSEN.**
- **Evaluated against the QUALITY bar (Contrarian's objection: 'a template is not narration — a permanent floor betrays *narrates what was done*'):** the lazy path passes because the floor is never the ceiling for any tile the user actually reads — every clicked tile converges to model-grade narration within minutes of its FIRST view and serves it from cache on every view thereafter; for terminal-status sessions the transcript is immutable, so that enrichment can never go stale; the interim state is honest ('summary generating…' is a badge OVER real content, never a spinner instead of content, and it never claims the floor is the full story); and the only tiles that live on the floor forever are tiles NOBODY EVER OPENS — for which 'narrates when clicked' is vacuously satisfied at click time by the floor plus the badge, converging to enrichment while the user watches.
- **Evaluated against the COST bar (Analyst's objection: 'model spend must not scale with tile count or click count'):** the lazy path passes because cost per session is bounded at ONE summarize_session run per session LIFETIME (the first open of a summary-less tile), at the identical unit cost of the existing summarize-on-finish hook — which already covers most NEW sessions, so the typical click is a $0 cache read; the lazy spend falls only on the clicked subset of the historical tail; a repeat click NEVER re-spends (cache); a failed generation does not retry in a loop (the v7 hook's semantics — the badge clears, the floor stands, the next OPEN may retry once); and no batch job, scheduler, or throttler ships at all.
- **Failure mode (both bars):** a failed or timed-out generation clears the badge and leaves the deterministic floor standing — never a blank pane, never a poisoned cache, never a blocked click, because the click path has ZERO synchronous dependency on the model.
- **Cost ruling recorded (the CUT is arithmetic, not taste):** Phase 0 counts the summary-less sessions in the real registry and records the arithmetic in the plan doc — (summary-less sessions) × (per-summary generation cost, tokens and $ if reported) — versus the lazy path's cost, which is the SAME per-summary cost paid only for tiles actually viewed, with the deterministic template covering the never-viewed tail for $0. That recorded arithmetic plus this three-way evaluation is the standing answer to any future 'why not backfill?' or 'why not template-only?' relitigation. **(Recorded — see `W1-GROUND-TRUTH.md` §3 for the arithmetic and the coverage-report method.)**
- ***Original objection & why this resolution survives it:*** *the two original objections pulled opposite ways — Contrarian: quality (a floor-only render fails 'narrates'); Analyst: cost (eager enrichment wastes spend on the unviewed tail).* The resolution survives BOTH simultaneously because the middle path is not a compromise that half-fails each bar but a sequencing that fully satisfies each on its own axis: quality is satisfied on the axis of *tiles the user reads* (every read tile converges to model-grade narration, cached forever), cost is bounded on the axis of *spend per session* (≤ one generation per lifetime, only for viewed tiles, $0 for the tail), and the honest interim badge is what makes the sequencing legitimate rather than deceptive — the UI never passes the floor off as the finished narration. A Shark pressing this lock must show a tile class or usage pattern where BOTH bars fail at once; neither original objection alone re-opens it.
- A session whose docs AND transcript are gone still narrates honestly: the template renders registry facts + 'no recoverable documents'.

**Tripwire severity (LOCKED, per the correctness-vs-performance doctrine).** Sidecar ABSENT/pruned is an expected environmental state → 'unmeasured (sidecar-pruned)' badge, healthcheck report.warn at most. Sidecar PRESENT but unparseable / yielding zero usage from a session that demonstrably had turns is a CORRECTNESS failure → RED: report.check(False) in the healthcheck (red banner), and in the live pipeline the finalize path writes an atomic 'capture-failed' record (a first-class enum state, visually distinct from both measured and unmeasured) — capture NEVER halts the session lifecycle and NEVER silently degrades to $0/unmeasured. The RED condition is deterministic (parse exception or zero usage blocks from a sidecar containing ≥1 message line), so it cannot flap on load.

**Endpoint auth rule (LOCKED).** Every NEW endpoint this plan introduces follows the existing token-auth pattern with no exception: POST endpoints token-authed via the standard check; GET/WS transports gate via `?token=` exactly like `term_ws`/`term_stream2`/`session_summary`. The plan's new surface is small and enumerated so this is checkable, not aspirational: the Layer-1 narration view data route (Phase 2), the WS attach-ack protocol extension (Phase 5 — rides the already-authed `term_ws` upgrade, no new unauthed socket), the Layer-2 orientation-job trigger (Phase 5), and any capture/ledger inspection route (Phase 4). A test enumerates the new routes against the auth table and asserts 401-before-substance for each; adding an endpoint outside this enumeration without extending the test is a BLOCKER.

## Additional plan-level locks carried here (cited by later waves)

**No-own-pricing-table (LOCKED, plan level).** Tokens + time are the measured facts;
`$` is shown ONLY when the engine itself reported nonzero `costUSD`. Anchor never
computes a dollar figure from a pricing table of its own — a session renders
`N tok · Xm (subscription)` on the Max-subscription host. (Master Plan Phase 5;
grounded by `intake/gap-closures.md` derived-G1 and `W1-GROUND-TRUTH.md` §1.)
**Rider (John, 2026-09-25, cockpit workflow Wave L):** a subscription turn that
reports tokens but no price MAY carry an estimate at the provider's published API
list price: always the word *estimated*, its own clause beside the reported total,
never folded into "reported"; the table is one dated, sourced file
(`steward_cockpit/api_list_prices.json`), and a model not in it stays unpriced.

**Orientation fork (LOCKED, Phase 0).** Read-only orientation narration
AUTO-EXECUTES as a read-only **plan-mode one-shot job** through `job_runner` (the
Gandalf-shard substrate — VERIFIED enforceable, `W1-GROUND-TRUTH.md` §2), never a
seeded turn on the live interactive PTY; any mutating/ACTION prompt remains v10
**paste-NOT-submit**. A test pins that no ACTION prompt is ever auto-submitted. If a
future engine drops plan-mode enforceability, the fallback is a RICHER Layer-1
render (transcript-tail + summary), never an unsandboxed auto-executed turn.

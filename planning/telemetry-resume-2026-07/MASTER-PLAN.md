# Master Plan (draft)

**North Star:** Every Anchor session — interactive ConPTY or one-shot job — leaves an honest, machine-verified trail of what it cost and what it accomplished, so the project rollup's numbers mean 'measured truth, not zero-by-omission,' and clicking ANY session tile reliably opens a warm terminal that narrates what was done, what was produced, and what comes next.

## Locked contracts (plan-level, relitigating any of these is a BLOCKER)

**Objection-survival rule (meta, LOCKED).** Each of the four previously-disputed resolutions below carries an explicit *Original objection & why this resolution survives it* clause. A Shark pressing a lock must press against that clause — showing the written resolution fails to defeat the recorded objection — not merely re-raise the objection the clause already answers. A lock whose survival clause is refuted is a legitimate BLOCKER; a lock re-argued without engaging its clause is relitigation.

**The click contract (LOCKED — dispute 1, pre-resolved: the passive warm view IS the narrating terminal, with in-view PTY escalation).** The North-Star phrase 'clicking ANY session tile reliably opens a warm terminal that narrates' is satisfied by a TWO-LAYER contract, and the plan formally defines each layer so 'warm' and 'reliably' are measurable, not adjectives:
- **The first-click sentence (LOCKED — test it VERBATIM against the North-Star clause 'clicking ANY session tile reliably opens a warm terminal that narrates'):** *The first click on any session tile — running, parked-idle, evicted-parked, done, failed, discovered/brownfield, or finished one-shot job — opens within 200ms a terminal-chrome window that narrates what was done, what was produced, and what comes next.* Every word is bound: 'any session tile' = the exhaustive Playwright tile-class matrix; 'opens' = exactly one click, no menu hunt; 'warm terminal' = Layer 1's terminal-styled window in the terminal window chrome, rendered from cached/durable local data; 'narrates' = the narration spine (done / produced / next); 'reliably' = the <200ms, structurally-never-blank budget. Playwright asserts this sentence per tile class, and the Judge evaluates the plan against THIS sentence, never a paraphrase.
- **Layer 1 — the warm narrated view (every click, every tile class).** First click opens the session window rendering the NARRATION SPINE — what was done / what was produced / what comes next — as a PURE DETERMINISTIC RENDER: no PTY spawn, no synchronous model call, no network. Reliability budget: renders in <200ms from cached/durable local data; it CANNOT be blank because its floor is a deterministic template over registry facts + doc roles (defined below) that is total over every registry/effort record. When no cached summary exists yet, Layer 1 additionally shows an honest 'summary generating…' badge while the EXISTING background enrichment runs (see the narration-floor lock) — a badge over content, never a spinner instead of content. This view IS the North-Star 'warm terminal' for a plain click, and the plan DEFENDS that identity rather than conceding it as a compromise: Layer 1 renders inside the SAME session-window terminal chrome Layer 2 lives in (same window, same monospace terminal surface styling, same title bar and controls), so escalation is an in-view pane transition, never a navigation or a second window — the user experiences one terminal window that starts narrating instantly and can go live in place.
- **Layer 2 — in-place live escalation ('▶ Resume live', same window).** An explicit control in that same window escalates to a live PTY IN PLACE (the window transitions; no second window). Reliability budget: the terminal pane swaps in ONLY after the WS attach-ack + replay-complete signal; if no ack within 5s the window shows an explicit, styled error state with a retry control and the narration still visible underneath — a blank pane is a protocol impossibility, not a rare bug. On escalation, the read-only orientation narration executes per the Phase-0 fork lock; ACTION prompts remain v10 paste-NOT-submit.
- **Click-path ruling (explicit, so the North-Star sentence is checkable against the plan text):** from any session tile the user performs exactly ONE action (the tile click) to reach a warm, narrating, terminal-styled window — Layer 1 — and exactly ONE further explicit action ('▶ Resume live', in the same window, never a new window) to reach a live PTY. The plan RULES that the North-Star sentence is satisfied at action 1: Layer 1 is 'a warm terminal that narrates' (terminal chrome + narration spine), and 'reliably' is its <200ms / structurally-never-blank budget. The live PTY is one explicit action away for every tile class — never more, and never a hunt through menus. The Playwright matrix asserts this 1-click/2-action path per tile class; a change that inserts a third action into the path to live is a BLOCKER.
- **Strict-literal-reading rejection (recorded, so this ruling is pressable rather than implicit):** the plan CONSIDERED the alternative reading in which 'opens a warm terminal' means a LIVE PTY at action 1, and REJECTS it with recorded rationale: (a) for done / failed / discovered / evicted-parked / finished one-shot-job tiles there is no live PTY to open — a spawn-per-click would mint new sessions and worktrees the user never asked for, mutating state from a read gesture; (b) a PTY spawn + engine launch is multi-second and engine-availability-dependent, so under the strict reading 'reliably' is unsatisfiable for most tile classes and the North-Star sentence becomes untestable as written; (c) Layer 1 IS a terminal in every sense the sentence binds — terminal chrome, terminal styling, the narration content — with the live PTY exactly one explicit in-window action away for every class. If the user rejects this ruling at the Stage-1 gate, the plan HALTs for re-framing rather than silently reinterpreting the sentence.
- ***Original objection & why this resolution survives it:*** *the objection was that a rendered view is not 'a terminal', so first-click-opens-a-render betrays the North-Star sentence.* The resolution survives because it does not weaken the sentence to fit the render — it BINDS every word of the sentence to a measurable property Layer 1 actually has (terminal chrome, narration spine, <200ms, never-blank), records and rejects the strict reading with three concrete reasons (state-mutation-from-a-read-gesture, unsatisfiable-'reliably', untestability), keeps live exactly one in-window action away for EVERY class, and — decisively — routes the residual disagreement to the user at the Stage-1 gate with an explicit HALT-for-reframing path instead of a silent reinterpretation. **The narration floor (LOCKED — dispute 3, pre-resolved: lazy on-first-click enrichment with an honest 'summary generating…' interim state; deterministic template as FLOOR; batch backfill CUT; seed-only rejected as ceiling).** 'Narrates' is satisfied at the floor by a DETERMINISTIC template over durable facts — 'ran <skill/lane> in <lane> (<dates>, <status>); produced: <doc-roles list with /report·/artifact links>; next: <NEXT-PROMPT.md / pending_paste / stage-derived next step>' — which requires zero model calls and is total over every tile class. **Three candidate narration models were evaluated, and the evaluation is recorded here so the choice is a ruling, not a default:** (i) **Degraded-seed-only** — the deterministic template forever, no model enrichment: $0 and always instant, but on long or conversation-heavy sessions registry facts + doc roles under-describe 'what was done' (a 3-hour research session renders as one lane/date line), so as a permanent ceiling it FAILS the North-Star 'narrates what was done' bar — RETAINED AS THE FLOOR ONLY, rejected as the ceiling. (ii) **Eager batch backfill** — pre-generate model summaries for every summary-less session: at any tile the user actually clicks it delivers narration no earlier than the lazy path (Layer 1 is already total and instant at click time), it spends the per-summary cost on the never-viewed tail, and it drags in a throttling/scheduling design — CUT as a phase deliverable. (iii) **Lazy enrichment on first tile-open with an honest generating state** — the click renders the deterministic floor IMMEDIATELY; when no cached summary exists, the open triggers the EXISTING background generation path (the v3 accordion machinery + summarize-on-finish, unmodified) and Layer 1 shows an explicit 'summary generating…' badge over the template; on completion (and on every later click, from cache) the enriched text replaces the template's 'what was done' line — **CHOSEN.**
- **Evaluated against the QUALITY bar (Contrarian's objection: 'a template is not narration — a permanent floor betrays *narrates what was done*'):** the lazy path passes because the floor is never the ceiling for any tile the user actually reads — every clicked tile converges to model-grade narration within minutes of its FIRST view and serves it from cache on every view thereafter; for terminal-status sessions the transcript is immutable, so that enrichment can never go stale; the interim state is honest ('summary generating…' is a badge OVER real content, never a spinner instead of content, and it never claims the floor is the full story); and the only tiles that live on the floor forever are tiles NOBODY EVER OPENS — for which 'narrates when clicked' is vacuously satisfied at click time by the floor plus the badge, converging to enrichment while the user watches.
- **Evaluated against the COST bar (Analyst's objection: 'model spend must not scale with tile count or click count'):** the lazy path passes because cost per session is bounded at ONE summarize_session run per session LIFETIME (the first open of a summary-less tile), at the identical unit cost of the existing summarize-on-finish hook — which already covers most NEW sessions, so the typical click is a $0 cache read; the lazy spend falls only on the clicked subset of the historical tail; a repeat click NEVER re-spends (cache); a failed generation does not retry in a loop (the v7 hook's semantics — the badge clears, the floor stands, the next OPEN may retry once); and no batch job, scheduler, or throttler ships at all.
- **Failure mode (both bars):** a failed or timed-out generation clears the badge and leaves the deterministic floor standing — never a blank pane, never a poisoned cache, never a blocked click, because the click path has ZERO synchronous dependency on the model.
- **Cost ruling recorded (the CUT is arithmetic, not taste):** Phase 0 counts the summary-less sessions in the real registry and records the arithmetic in the plan doc — (summary-less sessions) × (per-summary generation cost, tokens and $ if reported) — versus the lazy path's cost, which is the SAME per-summary cost paid only for tiles actually viewed, with the deterministic template covering the never-viewed tail for $0. That recorded arithmetic plus this three-way evaluation is the standing answer to any future 'why not backfill?' or 'why not template-only?' relitigation.
- ***Original objection & why this resolution survives it:*** *the two original objections pulled opposite ways — Contrarian: quality (a floor-only render fails 'narrates'); Analyst: cost (eager enrichment wastes spend on the unviewed tail).* The resolution survives BOTH simultaneously because the middle path is not a compromise that half-fails each bar but a sequencing that fully satisfies each on its own axis: quality is satisfied on the axis of *tiles the user reads* (every read tile converges to model-grade narration, cached forever), cost is bounded on the axis of *spend per session* (≤ one generation per lifetime, only for viewed tiles, $0 for the tail), and the honest interim badge is what makes the sequencing legitimate rather than deceptive — the UI never passes the floor off as the finished narration. A Shark pressing this lock must show a tile class or usage pattern where BOTH bars fail at once; neither original objection alone re-opens it.

## POST-BUILD FIX — R&D dashboard UI integration (2026-06-08, after first live use)
**Gap found on first real browser use:** the build's pytest-only gate (unit + route tests) passed, but the interactive browser layer was never assembled into `generate_html` — `render_projects_view_html` was orphaned (no caller), there was no R&D nav tab, no "+ New Project" UI, and no HTTP lane-launch endpoint (only the `lanes.launch_lane` function). So the dashboard "looked old" even running the new code. Root cause: wave acceptance criteria were unit-level; none asserted end-to-end browser reachability, and a pytest gate is blind to UI assembly.
**Fix:** wired the R&D surface into `anchor_gui.py` — R&D nav tab + `view-rnd` (folder-grouped projects view + "+ New Project" modal: create-folder / select-existing via dir browser); new endpoints POST `/api/rnd/launch_lane`, GET `/api/rnd/tail` (non-blocking incremental), POST `/api/rnd/answer_gate`, GET `/api/rnd/jobs`; project window (`/project/<id>`) gained Run Research/Plan/Build buttons + a live log/console drawer + in-session gate answer panel. New `tests/test_rnd_ui_wiring.py` (10 tests) incl. the regression guard that `generate_html` surfaces the entry point. Gate: **168 passed**.
**LIVE-VERIFIED this time (not just pytest):** booted the server on a throwaway port w/ tmp data dir + mock runner and drove it over HTTP — R&D tab present, created a project (persisted + tile rendered on `/`), launched a research job (`researchPrime`), tailed it to `done` (3 lines), project window had launch buttons + drawer. Live `anchor` service/8777 untouched.
**Lesson for future Foreman runs on UI features:** add an acceptance criterion (and a live smoke test) that asserts the feature is reachable/usable from the actual entry point, not only that its functions/routes work in isolation.

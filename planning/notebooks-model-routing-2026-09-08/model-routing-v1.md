# Plan A v1 - dashboard preferences reach every model caller

Planning draft for Grok review; not implementation approval.

Portability is in scope: ship the policy resolver, caller integrations, migration and conformance tests in Anchor and the affected distributed skills. Collaborators use their own Anchor settings, account login and supported model catalog. No dependency on John's username, absolute C:/dev paths, mirror contents or personal config.toml; imports resolve installed package locations. The default product policy and John's explicit latest/Ultra choice are distinct, and collaborators can choose the same policy.

## Outcome and evidence

When John selects ChatGPT for coder and terminal, new Doctor, Steward cockpit, terminal, Anchor job, Trio and Foundry calls use that selected family. Every ChatGPT production call uses the latest supported Codex model with Ultra. Current target is gpt-6-astra/ultra; Grok review remains Grok. Persona selection is independent.

The saved Anchor settings and mirror agree. Live Doctor status reports ChatGPT, but Doctor initializes Claude before status completes and has a backend-omitted legacy route. Cockpit Engine defaults to Claude and builds Claude stream commands. Anchor's isolated adapter pins Sol, Trio pins Sol/Terra, and Ramanujan explicitly pins Terra. Personal Codex Astra/Ultra defaults do not override these callers. The older notebook run halted with seat_unavailable; quota as the underlying cause is unproven.

## Changes proposed

1. **One effective policy.** Extend the existing Anchor settings/mirror contract with an explicit ChatGPT latest-supported/Ultra override. No second preferences file. Implement one shared resolved-policy contract consumed by Python and Node callers: provider, exact model, effort, role, settings revision, policy source, and capability check. Inventory every production launch site and explicit model/effort override before coding; include delegated agents, custom agent configs, manifests, adapters using ignore-user-config, and historical session restores. Historical tests and other providers are not blanket replacements.
2. **Precedence and timing.** Anchor's policy wins over stale environment, manifest and project pins for ChatGPT unless John explicitly changes policy. This is John's explicit override of regular/Heavy notches for ChatGPT, not a new tier definition. Resolve current family at each new seat/turn boundary; never change providers during an active turn. Freeze the exact model/effort for that turn and record settings revision. A preference change marks old sessions as old-provider, retaining history; the next new session uses the selected provider. Do not treat a Claude resume identifier as a Codex identifier.
3. **Latest means supported, not a guessed string.** Resolve the current official target against the installed subscription CLI's catalog. Cache a validated exact model/effort tuple with catalog timestamp; revalidate on policy/client changes and bounded startup refresh. Unsupported Ultra is visible, never quietly high. If live availability cannot be established, use a last-known-supported tuple only with an explicit stale status, otherwise report unavailable. Persist exact selection per turn; report requested/served model, effort and source. If Codex does not attest model, preserve model_attested:false and prove provider family instead of inventing an attestation. Official references: https://learn.chatgpt.com/docs/models and https://learn.chatgpt.com/docs/agent-configuration/subagents.
4. **Doctor.** Disable model-launch actions until authenticated status is loaded. Show auth/unavailable state without a default Claude launch. The backend-omitted API must resolve current durable policy on the server. Explicit provider buttons may create a clearly labeled one-session override; never silently change the dashboard. Correct races between status load, click and changed preferences server-side.
5. **Steward.** Add subscription Codex conversation transport using supported per-turn exec/resume, normalizing events, cancellation and terminal outcomes behind the existing Engine interface. Keep Claude's transport separate. Preserve transcripts and permission boundaries. On a family switch, start a new provider session with a concise visible history handoff, not blind full-transcript replay. Codex native IDs belong only to Codex. No raw API-key backend or general transport rewrite.
6. **Failure policy.** Classify authentication failure, unsupported model/effort, quota, provider crash and transport error separately. Use the documented capable-provider failover ladder, journal each attempted substitution immediately, show requested versus actual provider/model in UI and records, and retain partial output. Verification seats obey their own fail-closed rules; same-family review is stamped cross_model:false and never called Grok review. No ad-hoc retry loops or waiting for a reset when capable fallback remains.

## Proof and release order

First freeze caller inventory and precedence fixtures; then shared policy plus Doctor; then cockpit transport; then formal journal-backed Trio/Foundry changes. Each affected live launch site must have a policy conformance test. Tests cover stale pins, corrupt/missing preferences, a changed setting during an active turn, auth failure, quota/fallback, cancellation, resume and non-attested models. Use fake transports first. Final acceptance needs minimal real subscription turns with sanitized receipts and real Doctor/cockpit/terminal pixels after toggling away from and back to ChatGPT. Audit service-account versus interactive-user config visibility. Preserve dirty work and coordinate any release restart with active sessions; rollback does not delete histories or change saved family choices.

Skill changes must follow the formal Foundry improvement/sleep cycle: distill these failures, North Star gate, change proposal, focused evals and changelog. This review is not that implementation cycle.

Distribution acceptance: install the packaged Anchor/skills into a fresh profile without John's home/workspace, select the policy through supported setup, and prove the same resolver behavior with synthetic account/CLI fixtures plus a minimal live test using that installation's login. Capability failure is explicit when a collaborator lacks a subscription/model/Ultra; never promise that packaging grants account access. Version the settings/skill compatibility contract and fail visibly on incompatible combinations. Build release archives from an allowlist; exclude project content, teaching notebooks, personal settings, journals/transcripts, logs, screenshots and credentials. Inspect archive contents and run a secret scan before release; use synthetic fixtures only.

Needed because UI-selected preferences currently do not bind launch behavior; dropping centralized conformance leaves invisible bypasses. Cut: no other-provider model migration, permission expansion, quota bypass, new settings UI redesign, or historical fixture rewrite.

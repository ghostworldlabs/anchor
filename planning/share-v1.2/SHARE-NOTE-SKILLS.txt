Subject: My Claude Code skill suite -- 10 minutes to install

Hi [name],

Here's the skill suite I use for serious work in Claude Code -- 14 skills,
including the research/plan/build trio (researchPrime -> Crucible -> Foreman),
the Gandalf deep-think reviewer, and the Ecgberht project steward. Each one is
a self-contained playbook your Claude picks up automatically.

You'll need Windows 10/11 and git; no GitHub account, no admin rights, about
10 minutes. In a terminal:

    cd C:\dev                (create the folder if needed)
    git clone https://github.com/johncliechty/anchor-plus-skills.git
    cd anchor-plus-skills
    .\onboard.cmd

That's it. Onboard gets Python if you don't have it, walks a short dialogue,
and registers the skills for Claude Code -- check that
%USERPROFILE%\.claude\skills now lists them. Then just talk to Claude:
"/gandalf review this design", "use researchPrime to investigate X",
"use crucible to plan Y". Nothing spends your Claude subscription without an
explicit action by you.

One more optional command, and I recommend it. The skills are built to run
long jobs unattended -- an hour-long build that posts a status table every ten
minutes instead of stalling on permission prompts. To get that behavior (it's
how I run them), first read AUTONOMOUS-MODE.md in the folder you just
cloned -- it says exactly what this grants -- then:

    python share_agent_rules.py install --settings

It writes only to your own Claude config, never overwrites a setting you
already made, keeps a backup, and "python share_agent_rules.py remove" undoes
it.

Two honest notes:

- The repo also contains my Anchor dashboard -- ignore it for now; I'll send a
  separate note when that's ready to try. Nothing dashboard-related runs
  unless you deliberately start it.

- The skills use YOUR Claude Code subscription and run best with a second
  model family configured for cross-checking; without one they'll honestly
  stamp their output "cross_model:false" rather than pretend. That stamp is
  correct behavior.

If anything misbehaves: "python doctor.py" (free, no AI calls) and send me
what it prints. Upgrading later: "git pull", then re-run onboard.cmd once (it is
idempotent, and registers any new skills the release added).

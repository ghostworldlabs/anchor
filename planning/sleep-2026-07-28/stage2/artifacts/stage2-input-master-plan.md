# Master Plan (draft)

**North Star:** On branch v1.2, John can open, run, stop, and restart real Anchor work — including Doctor diagnose and session attach — without meeting a dead control, a silent zero, a mislabelled empty, or a preview that dumps raw binary. Every surface that claims health, usage, or diagnose either works end-to-end or fails with a named, user-visible state (unknown ≠ empty ≠ zero). Cost never fabricates dollars. Nothing in this effort ships to v1.1.x collaborators. Steward conversational proof is a post-build validation session (S1), not a silent claim of this build.

## Success criteria
- Dead controls eliminated for Retry (session attach), Diagnose (Doctor), and a single restart control — work or not shown.
- Attach path honesty: timeout classified as timeout (not unknown-session); error UI does not double-print; Retry re-issues a viable action or explains why not.
- Usage/time/cost surfacing: dashboard, workbench tiles, and session chrome render the rollups **proven to exist by the Phase 1 Rollup Evidence Gate** (query + row count + sample row); a rollup that is not proven is not "surfaced" — its aggregation becomes its own wave, and the surface renders a named `pending` state until that wave is GREEN. Cost labelling is derived from `cost_state` and **never** from the numeric value: a zero cost renders `(subscription)` only when `cost_state == subscription_covered`, and a zero with `cost_state == unmeasured` renders unmeasured. `$0.00` is never rendered as a fact; unmeasured engines show a labelled unmeasured state, never blank and never a fake zero.
- Doctor actually doctors: Diagnose runs a real diagnosis (not shell/seed/plan-only theater); banner→Doctor handoff carries issue payload; Claude/Gemini/Grok each report independently.
- Stop/summary/restart: stopping leaves a tile summarizing in-flight work; **exactly one restart control per enumerated restart context** — no context offers two competing restart controls, and each control carries its scope name and its preserved/lost contract (cross-context unification is explicitly not in scope); restart quality is documented and testable against that written contract.
- File preview: shared preview path shows human-friendly Word/PPTX/Excel/PDF (reuse working new-window path); binary no longer dumps as text.
- Projects default collapsed: folders open collapsed by default; user preference remembered; root cause is real JS/CSS path.
- Cadence is real: status cadence owned by Anchor from live telemetry on a timer, not prose that looks like a scheduler.
- Gates: surface-bearing waves have failure-state tables with unknown and empty as separate rows; scoped pytest gate-command per wave with -v; UI waves assert on rendered HTML + node --check; delta-coverage for new routes/handlers/frontend.
- Handoff hygiene: doc-trio + foreman.config.json only under planning/sleep-2026-07-28/stage2/; Foreman cwd that directory; root foreign artifacts untouched; commits land per wave; EXECUTION-LOG appended; attestation count reported.

## The exit register — closing the escape-hatch chain

The criteria above are an honesty framework. A rigorous honesty framework with a complete set of legal exits from honesty is not an honesty framework, and the exits in this plan compose into a single legal path: inventory returns STUB → reclassified "not available on this build" → cost spot-check fails → ships "provisional" → out-of-criteria surfaces close as "documented with reason" → S1 fails → findings routed to follow-on → status reads "ten criteria met, North Star pending." Every step of that chain must be individually legal for the plan to be executable at all; the chain as a whole must be illegal, or the acceptance system does not gate the North Star. The following rules make it illegal.

- **Exits are enumerated and numbered, not improvised.** The only legal exits in this build are E1 `not available on this build`; E2 `provisional data`; E3 `documented with reason` (out-of-criteria surface); E4 `reduced-instrument path` (see the instrumentation budget); E5 `not verified — awaiting John` (see John-in-the-loop scheduling); E6 `S1 finding routed to follow-on`. Any degradation that is not one of these six is a plan amendment under the standing renegotiation rule, not an exit.
- **Every exit carries John's dated signature.** An exit is taken by writing a register row — exit id, criterion degraded, the evidence that forced it, what the user sees instead, date, John's confirmation. An unsigned exit is a HALT, not a default. **At plan time John has signed for zero exits.** None are pre-authorized; every one is signed live, in the wave that needs it.
- **Exits are scored as a conjunction.** Two exits taken against the same criterion, or four signed across the whole build, force a HALT and an explicit re-baseline with John before any further wave starts. Scoring hatches one at a time is how each looks reasonable and the set looks like a shipped North Star.
- **No exit may be justified by another exit.** Specifically: E1 requires an ABSENT verdict with a transcript showing the absence — a STUB verdict may never be reclassified to E1; a STUB is `build it` or a signed E1 with independent evidence of absence, never an automatic downgrade. E2 may never be justified by an unproven accessor. E3 may never be justified by "the wave that would have fixed it took E1."
- **E2 does not apply to dollars.** If the Phase 0 rollup spot-check shows cost numbers are wrong, cost surfaces render `measurement_failed` — they do not render a number under a "provisional" label. Fabricating dollars with a disclaimer is still fabricating dollars, which the North Star forbids without qualification. E2 remains legal for usage and time counts only, and only with an `as_of` stamp and post-hoc reconciliation.
- **E3 is not a licence to leave a lie on screen.** For an out-of-criteria surface, "documented with reason" is a legal close only when the surface is already honest, or is removed from view. A surface that renders a fabricated value, a mislabelled empty, or an ambiguous zero is fixed or disabled — documenting it and shipping it is not a close.
- **E6 has a closed complement.** An S1 finding that reproduces one of the four North-Star violation classes — dead control, silent zero, mislabelled empty, raw-binary preview — is a build-blocking defect and may not be routed to follow-on. E6 is legal only for findings outside those four classes.
- **The status string carries the exits.** With any exit signed, terminal status reads verbatim `ten criteria met with N signed exits (E<ids>); North Star pending S1`. The unqualified phrase "ten criteria met" is reserved for a build with zero signed exits, and is otherwise a reporting defect.

## Instrumentation budget — the honesty framework must itself ship

The opposite failure of this plan is not dishonesty but weight: a harness so thorough that the surfaces never get built, and John ends the effort with an excellent conformance suite and a still-dead Diagnose button. That outcome fails the North Star as completely as a lying control does, and it is the more likely of the two given the volume of machinery in Phases 0–2.

- **Load-bearing versus discretionary, decided now.** Load-bearing and never dropped: the named-state vocabulary + render primitive, the tri-state conformance harness, the end-to-end trace artifact schema, the `cost_state` enum, and the zero-inference lint. Discretionary and degradable: breadth of fault injection, screenshot/recording capture, delta-coverage tooling, the null-preservation audit, the mechanical commit cross-check.
- **The reduced-instrument path (E4) is defined before it is needed.** If Phases 0–2 have not completed by the point at which surface work must start, the build drops to the reduced path — load-bearing machinery only, discretionary items in their named lighter forms (fault injection reduced to one induced fault per failure reason; screenshots replaced by a captured rendered-HTML snapshot; delta coverage replaced by the enumerated per-handler test list). Taking E4 is a signed register row, not a silent narrowing.
- **New gates are budgeted.** Any gate, check, or artifact added mid-build must either name the one it replaces or be logged against the budget with the wave time it costs. Ratcheting the harness heavier in response to a finding is a decision with a price, and the price is written down.
- **Phase 0–2 output is capped to its named artifact list.** Anything discovered in those phases that is not on the list is a Grasscatcher entry, not a new wave.

## Likelihood register — what will probably go wrong, not what could

A gap that the plan *permits* and a gap the plan *makes likely* are different objects and get different treatment. The permissive gaps are closed by the exit register above. The three likely failures are these, each with its mitigation named in the phase that owns it.

1. **The John bottleneck stalls the build.** Highest likelihood, lowest perceived severity. Mitigated by capture-once-replay-many artifacts and the max-wait rule below, not by asking John to be more available.
2. **Instrumentation overrun consumes the surface waves.** Mitigated by the budget above and the pre-defined E4 path.
3. **Phase 1 discovers ABSENT capabilities late, re-sizing the build after waves are written.** Mitigated by ordering — Phase 1 completes and its verdicts are reviewed with John *before* the wave list is finalized — and by the standing rule that a `build it` verdict gets its own wave rather than being absorbed into a surface wave.

## John-in-the-loop scheduling

John is a required input to evidence, signatures, and S1. Treating that as an administrative detail is how the build stalls.

- **Max wait is 48 hours per John-dependent item.** On expiry the item takes E5: the affected surface ships in its named `unknown` / `not verified` state, the criterion is recorded as `not verified — awaiting John` (never GREEN), and the wave proceeds to the work that does not depend on it.
- **Alternate producers, where one exists.** Transcripts, queries, sample rows, and profile state are captured once as versioned artifacts and replayed by the harness; John is not needed live to re-run them. Where an alternate producer exists it is named in the item; where none exists that is stated.
- **Live-John items, exhaustively:** the Phase 0 verification-task confirmation (hard blocker, no substitute, no E5), the shared-artifact ledger sign-off, every exit-register signature, the Phase 1 verdict review, and S1. Everything else has a capture-and-replay path or an E5 fallback.

This is a defect-remediation build on Anchor branch v1.2 whose central risk is not difficulty but dishonesty: wiring controls to capabilities that do not exist, surfacing numbers that were never aggregated, and calling a bound handler evidence. The plan therefore front-loads evidence: nothing is wired, surfaced, or labelled until a transcript from John's real v1.2 environment proves the underlying capability, rollup, or state actually exists. Phase 0 fixes the reproducible verification task, the containment smoke run, the shared-artifact ledger, and the coverage-toolchain truth. Phase 1 produces the Capability Inventory and Rollup Evidence Gate — the two artifacts that determine what the surface waves are actually allowed to claim, and that reclassify any control from 'wire it' to 'build it' or to a named 'not available on this build' state. Phase 2 builds the shared machinery (named-state vocabulary + render primitive, cost_state enum migration, tri-state conformance harness, fault-injection utility, screenshot capture, EXECUTION-LOG schema) so no surface wave hand-writes its own assertions or invents its own labels. Phase 3 is the surface work in dependency order — attach honesty, usage/time/cost, Doctor, stop/restart, preview, projects-collapsed, cadence — each gated on an end-to-end trace, per-reason induced faults, visible-text-node assertions, and a human-verification artifact. Phase 4 sweeps the controls the ten criteria do not name and closes the traceability matrix. Phase 5 is S1, the post-build validation session that is the only gate authorized to declare the North Star met; until it returns a verdict the build's terminal status is 'ten criteria met; North Star pending S1'. Two standing rules run through every phase: any criterion made unachievable by a discovered constraint is renegotiated with John as a logged plan amendment, never satisfied cosmetically; and every attestation count is host-computed by the orchestrator, never accepted from a sub-agent.

## Phase 3 — Phase 2 — Enabling Machinery (shared harnesses, vocabulary, and the cost_state migration)

Six of the ten criteria are variations on one problem: distinguishing unknown from empty from zero, honestly, on every surface. Building that discrimination once — as a shared vocabulary, a shared render primitive, a shared conformance harness, and a shared fault-injection utility — is the difference between seven surfaces that agree and seven surfaces that each invented their own labels and their own passing assertion. Critically, a shared conformance harness cannot be written to pass the surface it is written against, which is the specific failure mode of hand-written per-wave assertions. This phase serves SC-3, SC-4, SC-9 and every honesty clause in the North Star. No surface wave starts before its enabling wave is GREEN.

**Near-term specifics:**
- Shared named-state vocabulary + render primitive: one documented set of states — measured / pending / unknown / empty / zero / unmeasured / failed / unavailable / unclassified — and one UI component that renders them with distinct visual treatment. Every surface consumes it rather than inventing its own copy and styling. (I57)
- cost_state enum migration: measured / subscription_covered / free_tier / unmeasured / measurement_failed, stored alongside the numeric cost as an additive nullable column with existing rows defaulting to unmeasured. Reviewed against the Phase 0 branch-isolation resolution; feature-flagged off for v1.1.x per the shared-artifact ledger. (I12, FM-03)
- Grep-able lint/test that fails on any comparison of a cost value to literal zero for labelling purposes — banning the inference 0 ⇒ subscription anywhere in the codebase. This is a gate command, not a convention. (I13, FM-03)
- Repo-wide lint forbidding `||` fallbacks and template `default:` filters on any value in the cost/usage/health namespace, requiring `??` or an explicit null check. This catches the exact class of bug where a legitimate 0 is swallowed into 'unknown'. (I16, FM-04)
- Standing rule enforced as a gate check: no number is computed inside a template. Every rendered number traces to a named accessor, and each accessor is unit-tested against a fixture with known counts. Grep for arithmetic in template files as a gate command. (I10, FM-02)
- Null-preservation audit across the serialization stack: check that serializers, dataclass/TypedDict defaults, and ORM coercions do not fill None with 0 or '' between the accessor and the DOM. Output is a short table of every coercion point found, with a fix or a justification per row. (I17)
- Shared tri-state conformance harness (unknown / empty / zero) that every surface wave must instantiate rather than hand-write: seeds all three states end-to-end and asserts three distinct strings in rendered HTML. (I15, FM-04)
- Shared fault-injection test utility — force timeout, force transport error, force auth failure, force empty result, force null cost — reused across the attach, Doctor, telemetry and cost waves, so induced-fault testing is cheap enough that every wave actually does it. (I60)
- **End-to-end trace artifact schema — the load-bearing definition, written as a schema and not as a sentence.** The whole "no dead control" claim rests on what counts as an end-to-end trace, so the trace is a validated artifact with required fields, and a wave's acceptance runs a validator against it. Required fields, every one of which must be **absent or empty if the control is dead**:
  - `control_id` and `invocation` — which control, and the recorded user-level interaction (click/keypress) that started the trace, not a direct handler call.
  - `handler_entry` — handler name + file:line reached, with timestamp.
  - `capability_call` — the outbound call the handler made: target function/endpoint, arguments, timestamp. **A trace whose `capability_call` is null is the signature of a dead control** — a handler that ran and reached nothing.
  - `external_observable` — the side effect *outside the process under test*, named per control at wave-scoping time: a row written (table + primary key + a post-hoc SELECT returning it), a file created (path + size + checksum), a process spawned (pid + exit status), or a network request recorded (method + URL + response status). Prose descriptions are not values; a named row/file/pid/request is. **This is the field that would be absent if the control were dead**, and it is the field the validator checks hardest.
  - `render_observable` — the visible text node produced, captured via the strengthened UI assertion helper, plus the named state it rendered.
  - `elapsed_ms` and `as_of` — so a trace that "passed" by never completing is visible.
  - `trace_result` — one of `completed` / `failed_with_named_state` / `dead` (handler reached, no capability call) / `invalid` (schema incomplete). `dead` and `invalid` are wave failures. `failed_with_named_state` is a pass **only** when the named state is in the wave's failure-state table and rendered distinctly.
  A trace missing any required field is `invalid`, not "mostly passing." Waves do not hand-write traces; they emit them through this schema.
- Strengthened UI assertion helper: 'string present in a visible text node' — element not display:none, not aria-hidden, not zero-size, not inside a collapsed container. String presence in markup is explicitly not evidence of user-visibility, and this is stated in the plan. (I39, FM-13)
- Cost fixture set with one row per cost_state, and the acceptance that five visibly distinct labels render — asserted on the visible text node and reviewed by eye in an attached screenshot. (I14, FM-03)
- `as_of` stamping infrastructure: every telemetry-derived value carries an as_of timestamp, and the render primitive expresses staleness explicitly ('as of 4m ago' / 'stale — last update 2h ago'), so a dead cadence surfaces as a named state instead of a frozen number that looks current. (I34, FM-05)
- Failure-state table template with a mandatory terminal `unclassified` row whose rendered string is honest ('Unexpected failure — <raw reason>') and whose occurrence is logged with the raw signal for later classification. Tables are living artifacts, amended per wave. (I37, FM-14)
- Per-wave gate discipline fixed: each wave carries its own scoped pytest gate command with -v, written into the wave doc verbatim so the orchestrator runs exactly what the plan specifies — no whole-suite run standing in for a scoped gate, no gate command invented at run time. UI waves additionally assert on rendered HTML and run `node --check` (hygiene only, never evidence of honesty). Delta-coverage required for new routes/handlers/frontend, using the toolchain proven in Phase 0 or its named substitute. (I42, SC-9, FM-13, FM-15)
- Orchestrator-side attestation mechanics: the orchestrator (not the sub-agent) runs the suite and writes the pass count, file paths, and test names into the EXECUTION-LOG; it re-runs a sample independently. Any number an agent produced is stamped as a claim, not evidence. (I50, FM-22)
- Mechanical per-wave commit cross-check: files-touched in the wave's commit diffed against files-required by its acceptance criteria. A wave whose commit does not touch the files its criteria name is flagged regardless of test results. (I51, FM-22)

**Deferred (explicitly):**
- Deferred: applying the primitive and harnesses to each surface — that is Phase 3, wave by wave.
- Deferred: any cost_state backfill beyond defaulting existing rows to unmeasured; richer historical classification is out of scope for v1.2 and named as such.
- Deferred: retrofitting the named-state primitive to surfaces outside the ten criteria — that is scoped in the Phase 4 audit wave.
- Deferred: if Phase 0 concluded the cost honesty criterion cannot be fully met under isolation, the migration is scoped down here per the logged renegotiation rather than replaced by a render-layer cosmetic.

## Phase 4 — Phase 3 — Surface Waves (attach honesty, usage/cost, Doctor, stop/restart, preview, projects-collapsed, cadence)

This is the user-visible remediation: the phase where dead controls stop being dead and silent zeros acquire names. It runs strictly after Phases 1 and 2 because each wave's scope was set by the Capability Inventory and each wave's assertions come from shared harnesses it did not write. The universal acceptance standard here is the end-to-end trace — click → handler → capability → observable side effect, captured as an artifact — because a test proving only that a handler was called is precisely the evidence that lets a dead control ship GREEN. This phase serves SC-1 through SC-8 directly.

**Near-term specifics:**
- Universal wave acceptance standard, stated once and applied to every wave in this phase: acceptance is an end-to-end trace conforming to the **Phase 2 trace artifact schema** — `control_id` → `handler_entry` → `capability_call` → `external_observable` → `render_observable`, validated mechanically, with `trace_result == completed` or `failed_with_named_state`. A test that only proves the handler was bound or called produces a trace with a null `capability_call`, which the validator marks `dead` — so this class of evidence is not merely discouraged, it fails the gate. Each wave names its `external_observable` (which row, which file, which pid, which request) as part of its scoping, before the work starts. The wave also re-runs and attaches the post-change transcripts for every capability it touched. (I4, FM-01)
- Attach honesty wave (SC-1, SC-2): typed AttachResult object carrying an explicit reason enum — unknown_session, session_ended, timeout, transport_error, unauthorized, unclassified — constructed at the innermost frame that still holds the signal (identified in Phase 1) and propagated upward as a value, never re-raised as a generic exception that loses type at a shared catch. (I5, FM-08)
- Attach induced-fault set, one per reason, each asserting a distinct rendered string: bogus session ID, killed session, artificial delay past the deadline, blocked port, revoked credential. Two reasons collapsing to one string is a wave failure, stated as such in the acceptance criteria — notably, timeout must classify as timeout and never as unknown-session. (I6, FM-08, SC-2)
- Single error-rendering channel for the attach surface: one component owns error display, and the double-print test asserts exactly one occurrence of the error string in the DOM (count == 1, not >= 1). Fixing double-print by hiding one copy with CSS is explicitly disallowed. (I7, SC-2)
- Retry viability predicate: Retry derives from the reason enum whether a re-issuable action exists. Viable → re-issue and show what is being retried; not viable → the button renders a named 'cannot retry — <reason>' state. Retry never renders as an enabled control that re-issues nothing. (I8, SC-1, SC-2)
- Usage/time/cost surfacing wave (SC-3): dashboard, workbench tiles and session chrome each call the named accessor recorded in the Phase 1 evidence gate, for each rollup the gate proved exists. **Cost labelling reads `cost_state` and never the numeric value** — `subscription_covered` renders `(subscription)` with its reason, `unmeasured` renders the labelled unmeasured state, `measurement_failed` renders as failed, and a numeric zero is rendered as a dollar figure only when `cost_state == measured`. The zero-inference lint is a gate command on this wave, so the render path cannot recreate `0 ⇒ subscription` locally. Any rollup the Phase 1 gate did not prove renders `pending` and is surfaced by its own aggregation wave, not by this one. Tri-state conformance harness instantiated, not hand-written. (I9, I15, SC-3)
- Practical-usefulness acceptance alongside every honesty acceptance: after the named reproducible task completes, the tiles must show real numbers within a stated window (60s). A surface that renders 'unknown' perpetually is a wave failure, not a pass. Where the Phase 1 latency measurement shows data arrives late, render 'pending — measuring' with an as_of stamp and a refresh, plus post-hoc reconciliation that updates the tile when the real number lands. (I35, I36, FM-20)
- Doctor wave (SC-4): Diagnose runs a real diagnosis — not shell/seed/plan-only theater. Claude, Gemini and Grok each report independently, each rendering its depth label from the Phase 1 taxonomy next to its result ('Claude: live call OK', 'Grok: credentials present, not exercised'). A bare green check with no depth label is forbidden. (I18, FM-07)
- 'No diagnostic available' as an explicit fourth Doctor state — not a pass and not a failure. Any engine without a real diagnostic renders it. (I19, FM-07)
- Forced-failure fixture per engine (wrong key, unreachable endpoint) proving the diagnostic is real: a broken credential must produce a distinguishable failure state. A check that returns green against a wrong key is a wave failure. (I20, FM-07)
- Typed, versioned banner→Doctor handoff payload (issue id, engine, raw signal, timestamp), with a test asserting the payload arrives at Doctor and pre-selects or pre-populates the named issue rather than dropping the user on a generic Doctor page. (I21, SC-4)
- Stop-summary wave (SC-5): the summary is designed from the Phase 1 persisted-state inventory. Thin honest content — 'Stopped at step 3 of 8; 2 files written; partial output not retained' — is an acceptable named state. If the inventory triggered the checkpointing contingency, this wave depends on that wave rather than papering over it. (I23, I24, FM-11)
- Restart waves (SC-5): each enumerated restart context gets its scope-named label, its stated preserved/lost contract, and a scope-naming confirmation where blast radius is large. 'Restart quality' is a written contract per restart scope — what is re-run, what state is carried, what is discarded, what the user sees during the transition — so SC-5's 'documented and testable' clause has an object to test against. Unification is not performed. (I22, I25, FM-10)
- Preview wave (SC-6): explicit content-classification step in the shared preview path — magic-byte detection + declared content type + size ceiling — resolving to named states: text preview / image preview / document preview / 'binary file — N bytes, download' / 'too large to preview' / 'unsupported type — download'. Office/PDF handled per the strategy chosen in Phase 1, named with its dependency. (I27, I29, FM-06)
- Preview acceptance fixture set: UTF-8 text, invalid-UTF-8 bytes, PNG, PDF, DOCX, XLSX, PPTX, zero-byte file, oversized file. Raw binary rendered as text is a hard fail, asserted negatively — no control characters or replacement characters in the rendered node. (I28, FM-06)
- Projects-collapsed wave (SC-7): fix applied at the real source identified by the Phase 1 provenance finding — JS/CSS path, server attribute, or persisted preference. Folders open collapsed by default and the user's preference is remembered. Ships with a version-stamped preference key or a one-time migration so stale stored values are ignored when the default changes — shipped with the fix, not after John reports it still broken. (I30, I31, FM-12)
- Dual-profile verification standard for every UI-state fix in this phase: verified on a clean profile AND on John's existing profile with its real stored preferences. A fix verified only on a clean profile is not accepted. (I32, FM-12)
- Cadence wave (SC-8): status cadence owned by Anchor from live telemetry on a timer, implemented per the Phase 1 ownership finding — with pull-on-render or client-driven poll preferred where no supervised owner was proven. Every value carries as_of; staleness renders as a named state. (I33, I34, FM-05, SC-8)
- Per-wave fault-induction step, every wave in this phase: attempt three faults not listed in that wave's failure-state table; anything producing an unclassified or misclassified state must be added to the table before the wave closes. (I38, FM-14)
- Human-verification artifact per surface wave: a screenshot or short recorded interaction attached to the EXECUTION-LOG, plus an explicit written note in the plan that the automated gate does not certify visual distinguishability — so GREEN is never overread as 'a human could tell these apart'. (I40, FM-13)
- Per-wave honesty-budget review, answered in writing before the wave closes: 'what does this surface now claim, and what is the weakest evidence behind that claim?' A one-paragraph adversarial self-check that catches the lying-control class before the gate does. (I61)
- Per-wave shared-artifact checklist line — 'this wave modified these shared artifacts: ___' — requiring an empty answer or an explicit isolation note, with the collaborator smoke-check triggered on any non-empty answer and its outcome recorded. (I43, I45, FM-09)

**Deferred (explicitly):**

- Deferred: restart unification across contexts — explicitly not attempted; it is a separate decision John makes explicitly.
- Deferred: rich inline Office/PDF rendering if Phase 1 selected 'download to open' as the honest strategy; the named state ships and the richer rendering is backlogged.

The North Star says 'every surface that claims health, usage, or diagnose' — which is a wider set than the ten criteria enumerate. Left unfunded, that gap is where the build passes ten criteria and John still meets a mislabelled empty on the eleventh surface. This phase reconciles the North Star's scope with the plan's scope in writing and closes the traceability matrix so no criterion reaches S1 without a test behind it.

**Near-term specifics:**

Documentation is an acceptable outcome; silence is not. (I54, FM-18)
- Written reconciliation of the proxy gap: either narrow the North Star to the enumerated surfaces or fund the sweep, decided explicitly with John and logged. The plan states plainly that the ten criteria are a proxy for the North Star, not the North Star. **E3 `documented with reason` closes a surface only when that surface is already honest or has been removed from view**; a surface outside the ten criteria that renders a fabricated value, a mislabelled empty, or an ambiguous zero is fixed or disabled, and documenting it is not a close. - Failure-state tables consolidated: all states added mid-build via the per-wave fault-induction step are folded back into the canonical tables, and each table's terminal `unclassified` row is confirmed present with its honest rendered string and its raw-signal logging. (I37, I38)
- Handoff hygiene gate verified mechanically (SC-10): doc-trio + foreman.config.json exist only under planning/sleep-2026-07-28/stage2/; root foreign artifacts untouched, verified by a git-status diff taken before and after the run; commits landed per wave; EXECUTION-LOG appended per wave; attestation count reported as host-computed. (I49, SC-10)

## Phase 6 — Phase 5 — S1 Validation Session (the only gate authorized to declare the North Star met)

The build can meet ten criteria and still leave John meeting a dead control on the eleventh surface, because the criteria are a proxy and GREEN certifies automated assertions, not lived experience. S1 is therefore defined in the plan before the build, not improvised after it, and the build's terminal status is 'awaiting S1' rather than 'done'. An absent S1 verdict means the effort has not shipped. This phase is what makes the North Star's own 'Steward conversational proof is a post-build validation session (S1), not a silent claim of this build' clause structurally true.

**Near-term specifics:**
- S1 mechanics fixed in the plan before the build: who runs it (John), against which named reproducible task (the Phase 0 triple), what a failure produces, and where resulting defects go. (I53, FM-19)
- Free-traversal sampling protocol, not a checklist walk: John works freely for a defined session against the named task, opening, running, stopping and restarting real Anchor work including Doctor diagnose and session attach. Any dead control, silent zero, mislabelled empty, or raw-binary preview he meets — enumerated in the ten criteria or not — is a finding. (I55, FM-24)
- S1 verdict recorded as a required artifact. Until it returns, build status is reported verbatim as 'ten criteria met; North Star pending S1'. S1 is the only gate authorized to declare the North Star met. (I53, I55, FM-19, FM-24)
- Defect routing defined now, with a closed complement: S1 findings land in a named location with a named triage owner. **A finding that reproduces one of the four North-Star violation classes — dead control, silent zero, mislabelled empty, raw-binary preview — is a build-blocking defect and may not be routed to follow-on (E6 does not apply to it)**, whether or not the surface it appears on is one of the ten criteria. E6 is available only for findings outside those four classes, and each use is a signed register row. Any finding that invalidates a criterion triggers the standing renegotiation rule as a logged plan amendment rather than a quiet reclassification. (I47, I53)
- Explicit statement carried into S1's framing that the automated gate did not certify visual distinguishability — the screenshots are evidence a human can review, not evidence a human already did. (I40, FM-13)

**Deferred (explicitly):**
- Deferred: shipping to v1.1.x collaborators — nothing in this effort ships to them; that is a North-Star constraint, not a phase.
- Deferred: a second validation session, or a broader steward conversational proof beyond S1's defined scope.
- Deferred: remediation of S1 findings **that fall outside the four North-Star violation classes** — those are routed and triaged, and their fixes are scoped as follow-on work under the renegotiation rule (E6, signed), not silently absorbed into this build's status. Findings inside the four classes are not deferrable: they reopen the build.

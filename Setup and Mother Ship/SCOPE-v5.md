## 1. Resolve the mother ship first

Ask where the mother ship is before provider setup: **this computer will be the mother ship**, or **connect this device to an existing mother ship on another computer**. Identify the actual selected host throughout the walkthrough.

For a new mother ship, show the checklist for downloading/installing the Anchor service package and Foundry skills, choosing/creating the directories, starting/registering the service and confirming that it runs. Existing onboarding modules are reuse candidates; historical June/July completion receipts do not establish acceptance of this new flow.

For an existing mother ship, guide the Tailscale connection: both devices join the owner's personal network, confirm that the host is online/reachable, then pair securely with the token issued by the mother ship. A client connects to the existing organization; it does not install a second engine or recreate the goals. The downloaded client executable remains the shell. Phones/tablets are clients too.

The mockup demonstrates these actions with masked example pairing and explicit simulated status. It does not install software, join a network, generate real access tokens or persist them. Actual secure token storage and authentication details need verification during implementation planning.

## 2. Connect model sources second

Give the user a provider checklist for Claude, ChatGPT, Gemini and Grok, allowing **more than one separately named subscription for each provider**, plus optional API connections. Two Claude subscriptions are the concrete example. Subscription sign-in, API credentials and account tests belong to the selected mother ship. Remind users of that location while they are on a different computer, iPad/iPhone or Android device.

A connection test reports success/failure separately from the usage report. Show each subscription's observed allowance, window/reset and freshness, or “Not reported” when unavailable. Do not equate signed-in status with usable capacity. Capacity remains green usable, amber near limit, red exhausted and gray unknown, with words as well as color. Exact token counts are shown only when reported; an allowance percentage does not imply an exact token balance.

API spending, tokens and reporting period stay separate from included subscription allowance. A personal spending budget is not a provider account balance. Unknown cost/balance is “Not reported,” not zero. Values, report sources, models and account actions in the prototype are illustrative; provider reporting capabilities are not asserted as installed behavior.

Retain the lower-right Cave capacity tile and lower-left actual model/reasoning control, opening the shared detail surface used in Setup. Identify both provider and selected subscription/account. Allow choosing a ready alternate, including another subscription of the same provider, without blending their quotas. Exhausted, failed and unknown connections are not automatically confirmed-ready routes.

Show a configurable warning level and model-strength choice. John accepted **warn while keeping the frontier model and maximum reasoning until the user explicitly chooses a change** as the default for **Setup mockup — Refinement 1**, on October 4, turn `d1766e5a-bd83-4350-b45d-ff4539a1237b`. “Step down near the limit” remains an explicit user choice in the prototype. This settles the mockup's warning policy; it does not approve the whole walkthrough or authorize production behavior changes. Do not silently lower the live model or change current Anchor settings.

## 3. Organize a new mother ship from the Star Chart

After provider setup, a first-time mother ship starts organization in **Star Chart**, not Cave of Wonders. Choose a storage directory on a dev drive when available, or choose another location; `C:/dev` remains John's preference, not a claim that every user's computer has that drive/folder.

With **Aladdin** as default steward, describe or brainstorm major goals/objectives/campaigns. Within a goal, identify initiatives and their intended deliverables, such as a paper or code. Optionally nominate existing material and its location, or start new work in the chosen folder. After at least one goal/initiative and a selected storage location, preview Aladdin arranging that material and populating both Star Chart and Cave of Wonders. Do not move/consolidate real files without the later authorized mapping operation. A connected existing-host client reuses the host's goals and configured providers rather than running the first-time organizer or forcing another sign-in.

Keep the full requested project/folder mapping and backups in the map. Backup destination, retention, restore policy and the Organizer's eventual owner remain discovery details; they do not block this illustrative walkthrough. Distribution launches this same Setup flow, preserving independent acceptance of Setup and Distribution.
